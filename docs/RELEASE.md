# 发布与授权

## 当前通道：企业主体小程序（2026-10-27 绑定，审核中）

企业主体小程序账号已绑定，正在走微信审核。审核通过后发布**正式版**：
不再有 14 天与 15 人限制，并能拿到 mp 后台与 AppSecret（可以自己上传代码）。

提审前按微信要求备齐，缺一项就会被退回：

- **小程序备案**：主体材料 + 服务内容声明，管局审核约 5 个工作日
- **用户隐私保护指引**：本项目实际收集手机号、姓名与身份证（只存脱敏值）、
  常用地址、订单图片，需逐项声明用途
- **UGC 信息安全声明**：任务大厅有用户生成内容，必须填写
- **服务类目**：生活服务 / 跑腿，**个人主体不可选**，企业主体才能选
- **体验版先行**：体验版不需要审核、不需要备案，可先把成员拉进来验收

## 历史：WorkBuddy 试用版（2026-10-17 ~ 10-29，已停用）

WorkBuddy 的「试用版」= 微信**试用小程序**（服务商代注册），只能做一次性验证。
四条硬限制：

1. 14 天有效，不转正即注销
2. 最多 15 人体验
3. 一个微信号最多建 5 个
4. **不能转正式版**；且**没有后台、没有 AppSecret**（不能扫码登录公众平台、不能自己上传代码）

转长期通道的官方路径：分享面板「解绑」→「绑定已有小程序账号」→ 发体验版或正式版。

## 授权是「拉取式」的（试用版时期的排障记录，留档）

试用版**没有成员管理界面**，用户在后台找不到入口是正常的。正确流程：

```
分享二维码 → 对方扫码 → 首次触发「申请体验权限」
          → 创建者在微信「服务通知」里点开批准
```

**排障技巧**：忘了管理员是哪个微信号时，用不常用的微信扫预览码申请成为体验者，
**哪个微信号收到「小程序体验成员申请」，哪个就是管理员**。

## 上传失败的排查

微信 CI 的真实报错藏在 WorkBuddy 前端日志里：

```
C:/Users/<你>/.workbuddy/logs/renderer.log
搜索： [miniprogram:publish] publish failed
```

字段 `raw=` 是完整错误，`displayed=cleaned` 表示界面上那句是「洗过」的。

最常见的原因不是网络也不是体积，而是 **同一个函数被声明了两次**：

```js
// utils/api.js
function completeOrder(...) { }   // 275 行
function completeOrder(...) { }   // 284 行  ← 微信 CI 直接编译失败
```

`node --check` 抓不到（非严格 Script 里顶层函数声明是 var 作用域，重复声明合法），
只有 `new vm.SourceTextModule(src)` 能抓到 → 已固化进 `tools/check-mp.js`。
