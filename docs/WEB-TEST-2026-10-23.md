# 本地浏览器测试

## 运行方式与边界

```powershell
npm run preview:web
```

打开 `http://127.0.0.1:4317`。开发服务器仅监听本机回环地址，需先运行上述命令。
可用环境变量 `CAMPUS_PREVIEW_PORT` 改端口。

仓库是原生微信小程序，没有现成 H5 入口。本次新增 `tools/web-preview/`，在 430 × 844 浏览器 iframe 中加载**原始页面控制器、WXML 和 WXSS**，适配页面生命周期、数据绑定、点击、输入、滚动与本地存储。适配工具在 `tools/` 内，沿用现有打包忽略规则，不进入微信上传包。

登录、后台 API、选图、上传、AI 回答均为隔离模拟，不加载生产 Cloud SDK，不连接线上。宿舍选择器以普通输入框替代，导航栏由适配层呈现。该页面不是完整 H5 产品，也不等于微信开发者工具或真机测试通过。浏览器不能验证微信键盘、系统相册、授权、真实通知、RLS 或模型服务。

## 测试中新发现并修复的问题

客服用户消息使用 `.msg-row.mine`，但全局 `app.wxss` 存在：

```css
.home, .mine { min-height: 100vh; }
```

两条规则同时命中每条用户消息，使一条消息行至少占满整个视口。浏览器实测同一条单行用户消息：修复前 **844px**，修复后约 **68.17px**；计算后的 `min-height` 从 `844px` 变为 `0px`。

已把客服消息方向类改为 `.msg-mine` / `.msg-peer`，避免复用页面根类。新增回归检查：消息方向类不得与全局设置视口最小高度的页面类重叠。这个问题不会被页面控制器单元测试发现，必须连同全局 CSS 检查。
